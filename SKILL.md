Maddy On Page SEO Skill
A reusable SEO/content workflow for any website. The purpose is not to produce generic search-engine content. Every publish-ready page must satisfy search intent, be factually current, add useful information beyond common SERP coverage, and give the reader something practical they can act on.

Core workflow
Always work in this order:

Topic and page ownership
Search intent research
Live SERP and competitor-gap analysis
Primary/official-source research
Information-gain definition
Article/page structure and semantic content review
Internal-link map
Practical differentiator or asset
Fact verification
On-page SEO QA
Ready-to-publish output
Post-publish GSC feedback loop

Do not skip the information-gain step merely because the page is well optimized.
Mandatory publishing gate
Before treating an article as publish-ready, answer:
If the reader has already read the top five useful search results, what genuinely new and useful value does this page add?
If there is no strong answer, the article is not publish-ready. Research further, narrow the angle, add a practical asset, add verified analysis, or choose another topic.
Search intent rules

Determine what the searcher is actually trying to accomplish: learn, compare, configure, recover, verify, decide, troubleshoot, buy, or download.
Prefer specific problems, decisions, workflows, tests, failure modes, and implementation questions over generic definitions.
Do not write a generic “What is X?” article by default.
A generic pillar is allowed only when SERP opportunity, site architecture, or strategic cluster needs justify it.
Do not create content merely to fill an empty category.

Competitor research rules
Use live search results when current SERP research matters. For the main competing pages, identify:

Primary intent served
Common headings and repeated advice
Unique elements
Weak or outdated claims
Missing questions
Missing verification steps
Plan, pricing, or feature gaps
Missing practical context for the target audience
Poor examples or unclear implementation
Opportunities for a practical tool, template, table, test, or decision path

Competitor pages are evidence of what is already commodity coverage. Do not copy their structure just to be “more complete.”
Information Gain
Information gain is a mandatory content-quality standard.
Useful information-gain patterns include:

Current-year changes that alter what the reader should do
Primary-source interpretation in simple language
Decision matrices
Safe order-of-operations
“How to verify it worked” checks
Evidence/proof fields
Common false-positive or “looks correct but isn’t” situations
Audience-specific scenarios
Decision trees, worksheets, templates, or checklists that can actually be used
Calculators or testers
Original screenshots/testing only when actually performed
Original data or observations when available

Never invent first-hand testing, screenshots, experience, data, or results.
Source and fact rules

Prefer current primary/official sources relevant to the topic and industry.
Verify current-year facts, product details, pricing/plan availability, dates, deprecations, and recommendations before publishing.
Do not silently rely on an old article when a current official source exists.
Put authoritative external links near important claims when useful.
Separate confirmed facts from analysis or recommendations.
If a source does not support a claim, do not present the claim as verified.

Writing standard

Adapt tone and complexity to the website’s actual target audience.
Use simple, practical language.
Short paragraphs.
Direct “you” language where natural.
Explain jargon immediately.
Avoid filler and robotic phrasing.
Avoid habitual AI wording such as “delve,” “unleash,” “navigate the landscape,” “comprehensive” when unnecessary.
Length is determined by search intent and usefulness. Do not use a fixed word-count target as a ranking rule.

Semantic content review

Assign each page one primary reader task.
Put the direct answer near the start.
Organize sections in the order a reader decides, acts, verifies, and troubleshoots.
Include related questions only when they resolve a real follow-up within the page’s intent.
For material instructions, state conditions, how to verify the result, and what to do when it fails.
Remove repeated definitions, unnatural keyword variations, and sections added only for appearance of completeness.

Real-world evidence and cases
When a real case would improve the answer, look for credible documented examples. Check date and attribution. Never invent a real case. If none is found, state it clearly and use a labelled hypothetical only when useful.
Article implementation pattern
For important actions, include as many of these as useful:

What to do
Why it matters
How to do it
Exact steps when verified
Plan or requirement notes
Common mistake
How to verify it worked
What evidence to save
What to do if the expected result is missing

SEO rules

Use the primary keyword naturally in the SEO title, page title, introduction, relevant headings, and body.
Meta description: target 150–160 characters unless otherwise requested.
Keep the slug short, descriptive, and stable.
Treat Page Title/H1 and SEO title as separate fields.
Begin the copy-paste body with the opening paragraph (no H1 in the body when the theme already renders the title as H1).
Use internal links to relevant live pages on the same website with natural anchors.
Link to authoritative external sources for important claims.
Add a FAQ section only when genuine leftover questions remain.

Practical-asset rule
When the topic benefits from one, propose or create a genuine useful asset (checklist, worksheet, template, decision matrix, calculator, etc.). The asset should reduce work for the reader.
Cannibalization rules
Before proposing a new page:

Check whether an existing page already owns the intent.
Prefer refreshing an existing page when overlap is high.
Keep clusters useful rather than endlessly expanding variants.

GSC feedback loop
After publishing, use Google Search Console data when available to refine titles, meta, content, and internal links based on real queries and performance.
Stop conditions
Never mark an article publish-ready if required fields are missing, links are unverified, important claims lack sources, the page duplicates existing intent without a plan, or the information gain is only a longer rewrite of competitors.
Final quality question
Before calling anything ready:
If the reader has already read the best competing pages, why should they still find this page more useful?
If there is no strong answer, improve it or mark it as Draft.
